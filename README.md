# X5-Enot

Проект для прохождения анкеты кандидатом и просмотра результатов скоринга в HR-интерфейсе.

## Запуск в Docker

Из корня проекта:

```bash
docker compose up --build
```

После запуска будут доступны:

- Анкета кандидата: [http://localhost:4173](http://localhost:4173)
- Список кандидатов после скоринга: [http://localhost:4173/#/hr](http://localhost:4173/#/hr)
- Проверка бэкенда: [http://localhost:8080/api/v1/ping](http://localhost:8080/api/v1/ping)

## Основные ручки

- `GET /api/v1/quiz` — отдает структуру анкеты для фронтенда.
- `POST /api/v1/submit` — принимает ответы кандидата, считает скоринг и сохраняет результат в память.
- `GET /api/v1/hr/candidates` — возвращает список всех кандидатов, отсортированный по убыванию `total_score`.
- `GET /api/v1/hr/candidates/:id` — возвращает подробную карточку кандидата с аналитикой.

## Порог отбора

В HR-список попадают только кандидаты, набравшие `50` баллов и выше.

Это сделано для первичного отсеивания слабых анкет, чтобы рекрутер смотрел меньше нерелевантных профилей и быстрее фокусировался на кандидатах, которые ближе к требованиям вакансии.

## Как считается скоринг

Скоринг реализован как rule-based алгоритм на Go в [backend/scoring.go](/home/maria/X5-Enot/backend/scoring.go).

1. Технические навыки.
За каждый навык из целевого списка `Go`, `SQL`, `Docker`, `Kubernetes`, `Linux` начисляется `10` баллов.
Максимум за блок: `50`.
Если совпадений 3 и больше, в сильные стороны добавляется высокая релевантность стека.
Если совпадений меньше, формируются замечания про частичное совпадение или нерелевантный стек.
Если выбрано меньше 3 hard skills, добавляется слабая сторона про узкий набор компетенций.

2. Опыт и стажировки.
Опыт работы переводится в баллы функцией `pointsFromLevel(exp_level, 18, 5)`.
Это дает:
- `0` -> `0`
- `1` -> `5`
- `2` -> `10`
- `3` -> `15`
- `4` и `5+` -> `18`

Стажировки переводятся в баллы функцией `pointsFromLevel(intern_level, 12, 4)`.
Это дает:
- `0` -> `0`
- `1` -> `4`
- `2` -> `8`
- `3` -> `12`
- `4` и `5+` -> `12`

Сумма опыта и стажировок ограничивается максимумом `30`.
Если опыт высокий, в сильные стороны добавляется практический опыт.
Если `exp_level == "0"`, добавляется слабая сторона про отсутствие коммерческого опыта.
Если стажировок достаточно, добавляется сильная сторона.
Если `intern_level == "0"`, добавляется слабая сторона про отсутствие стажировок.

3. Доступность.
Баллы за выход на работу:
- `Завтра` -> `10`
- `Через неделю` -> `7`
- `Через месяц` -> `4`

Дополнительно:
- `Полный день` или `Гибкий график` -> `+5`
- `Офис` или `Гибрид` -> `+5`

Максимум за блок доступности: `20`.
Если кандидат готов выйти завтра, это идет в сильные стороны.
Если выбран вариант `Через месяц`, добавляется замечание про не самую быструю доступность.

4. Дополнительная интерпретация.
Если `achievements == "0"`, в слабые стороны добавляется отсутствие достижений в профильных соревнованиях.
Если сильные стороны по итогам расчета пустые, добавляется нейтральная формулировка о корректно заполненной анкете.

5. Итоговый статус.
После подсчета общего балла бэкенд выставляет статус:
- `top`, если `score >= 70`
- `review`, если `score >= 40`
- `delayed_reject`, если `score < 40`

Дополнительно для HR-ленты действует отдельный порог показа:
- кандидат появляется в списке только если `total_score >= 50`

В детальной карточке HR получает:
- `total_score`
- `analysis.strengths`
- `analysis.weaknesses`
- `analysis.score_details`
- `full_answers`
