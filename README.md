# 🦝 X5-Enot: Recruiting & Scoring System

Проект автоматизированного скоринга и анкетирования кандидатов для хакатона X5. 

## 📂 Что находится в ветке `merged`?
В этой ветке мы объединили фронтенд и бэкенд в единую монорепозиторную структуру для удобного развертывания через Docker.

- **`/backend`**: Сервер на Go (Gin). Занимается обработкой анкет, расчетом баллов (scoring) и аналитикой для HR.
- **`/frontend`**: Клиентское приложение на Vite/React/TS. Интерфейс квиза для кандидатов.
- **`docker-compose.yml`**: Файл оркестрации, который связывает оба сервиса, настраивает проброс портов и проверку состояния (healthcheck).

---

## 🛠 Технологический стек
- **Backend**: Go 1.26, Gin Framework, CORS Middleware.
- **Frontend**: React, TypeScript, Vite.
- **DevOps**: Docker, Docker Compose (Multi-stage builds).

---

## 🚀 Как запустить проект

Убедитесь, что у вас установлены **Docker** и **Docker Compose**.

### 1. Клонирование репозитория
```bash
git clone -b merged [https://github.com/your-repo/X5-Enot.git](https://github.com/your-repo/X5-Enot.git)
cd X5-Enot
```

### 2. Сборка и запуск
Запуск всех сервисов одной командой:
```bash
docker-compose up --build
```
*Команда автоматически соберет Go-бинарник, установит NPM-пакеты и поднимет контейнеры.*

### 3. Проверка работоспособности
После запуска проекты будут доступны по адресам:
- **Frontend**: [http://localhost:4173](http://localhost:4173) — Анкета кандидата.
- **Backend API**: [http://localhost:8080/api/v1/ping](http://localhost:8080/api/v1/ping) — Проверка статуса сервера.

---

## 🔌 Основные API Endpoints
- `GET /api/v1/quiz` — получить структуру вопросов.
- `POST /api/v1/submit` — отправить ответы на скоринг.
- `GET /api/v1/hr/candidates` — список кандидатов (для HR-панели).
- `GET /static/*` — доступ к медиа-файлам (картинки енотов).

---

## 📝 Важные примечания для разработчиков
- **Healthcheck**: Фронтенд зависит от бэкенда. Он начнет запуск только тогда, когда бэкенд успешно ответит на `ping`.
- **Static**: Изображения хранятся в `backend/static` и пробрасываются в контейнер через Volumes, что позволяет менять их без пересборки.
